# V5Notes 2.0.3 Release Notes

[简体中文](v2.0.3.md) · [English](v2.0.3.en.md)

**Release date:** 2026-11-17

Keep your ideas on your own server.

V5Notes 2.0.3 is a maintenance and enhancement release after 2.0.2. It focuses on desktop drag-and-drop feel, editor theme selection, a v5md upgrade, and a one-stop desktop package publish workflow. You can upgrade from any existing 2.0.x deployment; back up the database and upload directory first. This release adds **no new Flyway migrations**. The API / admin console can stay on 2.0.2 if unchanged, but the desktop client should be updated to 2.0.3.

In-app updater notes source: [v5notes-client2/releases/2.0.3.md](../../v5notes-client2/releases/2.0.3.md).

## Highlights

- **Click vs drag**: sidebar notes enter a “ready to drag” cursor on press and only start a real drag past a distance threshold; short presses still open the note, and the click after a drag is suppressed
- **Drag hint**: note-row tooltips explain “click to open, hold to drag” (zh-CN / en / zh-TW)
- **Editor themes**: the command palette can follow the app theme (Auto) or pin Paper, GitHub, Nord, Tokyo Night, Catppuccin, One Dark, Dracula, Solarized Light / Dark; the choice persists and is shared by the main editor and history preview
- **v5md 0.0.6**: the desktop app now locks `@v5md/core` / `@v5md/view` / `@v5md/vue@0.0.6` from npm instead of in-repo vendor tarballs
- **Desktop publish workflow**: new `publish-desktop.yml` builds macOS (Apple Silicon / Intel) and Windows x64 packages on `v*` tags or manual runs; `publish-update-feed` no longer listens to tags, avoiding incomplete `latest.json` races while packages are still uploading

## Fixes and improvements

- Dark-mode editor chrome leans on the v5md theme system; redundant client dark overrides are reduced
- Update feeds stay aligned with all three platform packages: `latest.json` is written / recomputed only when every update artifact (and `.sig`) is present

## Upgrade notes

No new system settings or database migrations in this release.

Upgrade steps:

1. Back up the database and upload directory (if you also upgrade the server)
2. API / admin: 2.0.2 builds remain fine; if you ship the latest repo build, confirm a clean startup (no new Flyway)
3. Install / update the desktop client to 2.0.3 (on macOS pick the Apple Silicon or Intel build; in-app updates match the host architecture)
4. When upgrading editor capabilities, publish and lock matching `@v5md/*` npm versions; local linking via `V5MD_LOCAL_ROOT` still works for development
