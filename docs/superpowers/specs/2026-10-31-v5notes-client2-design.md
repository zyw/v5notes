# v5notes-client2 设计稿（待评审）

## 意图

重新开发桌面笔记客户端，在现有后端和 Markdown 笔记格式上提供接近 Notion 的编辑操作：输入 `/` 选择命令、块操作柄、块类型切换和拖动排序。先用真实长文档检验编辑器的光标、撤销、中文输入和拖动，再决定是否需要 JSON 块模型。这里的“Notion 风格”指这些交互，不意味着首期实现数据库式页面、协作、嵌套任意块或 Notion 格式兼容。

用户已选择 **Markdown 优先**。本稿暂按 **Vue 3 + Tauri 2 桌面壳**设计；这是当前方案假设，尚待确认和跨平台验证。`v5notes-client2/` 在仓库中已存在，目前为空目录。本次仅产出设计，不创建应用或修改工作区外的 `v5md`。

## 已有基础与关键约束

- 现有 `v5notes-client/frontend/` 是 Vue 3 页面，笔记读写走 `/client/notes`；笔记 `content` 是后端 `note_notes.content` 的 Markdown 字符串，雪花 ID 在客户端按字符串处理。客户端登录使用自定义服务器地址、`clientPassword`、`pc_client`、`clientid` 与 Bearer token。目录/搜索/上传契约见 [客户端重构分析](../../client-redevelopment.md)。
- 工作区外的独立 `v5md` 项目有 `@v5md/core`、`@v5md/view`、`@v5md/vue`；Vue 组件 `V5Editor` 以 `v-model` 读写 Markdown，编辑器有 `getMarkdown`、`setMarkdown`、`format`、`undo`、`redo`、`focusAt` 等方法。现有代码已有解析偏移、编辑历史、中文输入处理、图片上传和源码模式；**当前没有 `/` 命令、块操作柄或拖动排序**。
- `v5md` 的 `setMarkdown` 会重建编辑状态和历史。它的编辑逻辑以 Markdown 字符串偏移和事务为基础，每次渲染会重新解析并替换文档区。因此块移动、命令选择不能通过外层组件拼接字符串再回写 `v-model` 实现，否则易丢撤销历史、选区和输入法状态。
- `v5md` 当前在 `createState` 中规范化换行符并去除开头 BOM。保持“Markdown 格式”意指继续保存 Markdown 字符串；对 CRLF/BOM 或复杂原文的逐字节保真需要用旧笔记样本实测，不能先验保证。
- 现有后端没有笔记版本号或冲突检查；并发修改默认存在后写覆盖先写的风险。首期不声称解决多设备协作或离线同步。

## 目标、范围与排除项

**首期目标**

1. 用原有账号登录并连接现有服务器；保留目录、搜索、笔记 CRUD 与图片上传的主要操作。
2. 笔记仍以 Markdown 原文读写，不改数据库、不引入 JSON 块字段。编辑器增加 `/` 菜单、块操作柄、块类型切换和拖动排序。
3. 显式保存，并在切换笔记、退出或关闭窗口时正确处理未保存内容；保存失败不丢草稿。雪花 ID 从请求到状态始终是字符串。
4. 在真实长文档上验证输入法、光标、撤销与拖动稳定性，记录决定是否升级数据模型的证据。

**首期不做**

- 任意嵌套块拖动、实时多人协作、离线编辑同步、数据库视图、任意块属性、块级服务端 ID。
- 自动迁移旧笔记或把整篇旧 Markdown 统一格式化；不把 JSON 当作服务端存储格式。
- 自动更新可在桌面壳稳定后设计；现有客户端的更新插件在三平台均未启用。

## 方案取舍

| 路线 | 好处 | 代价与决定 |
| --- | --- | --- |
| **Markdown 原文 + 在 v5md 内扩展块命令** | 复用现有解析、历史、Vue 组件，后端格式不变 | 必须准确界定 Markdown 块范围和分隔符；**本稿采用** |
| 在 client2 外层操作 DOM 或重写 `v-model` 字符串 | 看似集成快 | `v5md` 重绘文档且 `setMarkdown` 重置历史，光标和撤销难以正确维护；不采用 |
| 直接改用 JSON 块编辑器 | 更容易表示任意嵌套与属性 | 改服务端存储、旧数据迁移与双格式兼容成本高；长文档验证后再决定 |

桌面壳候选为 Tauri 2 与原生 Electron。本稿暂用 Tauri 2：保留 Vue 技术栈，桌面系统调用集中在小的适配层；若长文档 WebView 行为、上传或三平台构建验收不过，改用原生 Electron 仍可复用业务页面和 `v5md`。这是桌面壳选择，不改变 Markdown 优先的编辑模型。

## 产品交互

### `/` 命令

- 在普通段落或空白行输入 ASCII `/` 时出现贴近光标的菜单；随后输入文字筛选。上下键选择，Enter 执行，Esc 关闭；点击菜单项也可执行。中文输入法的组合输入期间不触发或执行命令，确认输入完成后再判断文本。
- 首期命令：正文、标题 1/2/3、无序列表、有序列表、待办列表、引用、代码块、分割线、图片。命令执行替换触发用的 `/` 与查询文字，并作为**一次撤销步骤**完成块转换或插入；选择后光标落在可继续输入的位置。
- 在代码围栏、公式、YAML frontmatter、表格单元格和行内代码中，`/` 仍是普通文本。非行首普通段落中的 `/` 也先作为普通文本；首期只支持行首命令，避免 URL、路径和正文中的斜线误触发。
- 菜单随光标和滚动定位，不能改变文档选区。失焦、切换笔记、Esc 或删除触发斜线时关闭；触发文本留在文档中仅在用户主动取消时保留。

### 块操作柄与类型

- 鼠标悬停可移动块的左侧显示操作柄；单击打开块菜单，含“上方插入、下方插入、转换类型、删除”；拖动操作柄进入排序。键盘用户通过命令菜单和明确的“上移/下移”动作使用同样的核心命令。
- 首期“块”是文档顶层段落、标题、引用、列表、围栏代码、分割线、图片、表格、公式块。列表作为**整体**移动；不拖动单个列表项或跨列表合并。YAML frontmatter 固定在文首，不参与拖动。代码、表格和公式块可整体移动，但不在内部显示可操作柄。
- 类型切换仅对 Markdown 能明确表达的类型开放：段落、标题 1/2/3、无序/有序/待办列表、引用。代码/表格等是插入命令，不承诺将已有复杂块无损转换为另一类型。选中区跨越多个块时先不显示转换动作。

### 拖动排序

- 拖动时显示插入线，放下才改变 Markdown；无效目标（自身、frontmatter 内、列表/表格内部）显示禁用态。放下后操作柄仍对应移动后的块，光标恢复到原块文本的相对位置。
- 一次移动进入一条撤销历史；Undo 恢复原文和选区，Redo 再次移动。保留块内原始 Markdown 写法（空格、列表标记、围栏语言及行内格式）。仅允许为维持块分隔所必需的换行调整，并将调整限定在源/目标边缘。
- 移动整段源码区间，不能对渲染后的 DOM 排序再反序列化。一次拖动不写服务器；落下后标记笔记为未保存。

## 实现位置与接口

```text
v5notes-client2/ (新建应用，Vue 3 + Tauri 2)
  ├─ 应用层：登录、目录、列表、搜索、编辑页、保存状态
  ├─ HTTP 层：沿用现有后端契约、字符串 ID、上传
  ├─ 桌面适配层：Tauri 2、关闭确认、托盘驻留（macOS / Windows）
  └─ 编辑页：@v5md/vue + 文件上传/保存接线

独立 v5md 仓库（需单独实施、测试与发布）
  ├─ core：根据 Markdown 偏移执行块移动、插入和转换的单次历史事务
  ├─ view：识别当前块、操作柄、拖动反馈、/ 菜单与键盘/IME 事件
  └─ vue：继续暴露 Markdown 字符串与编辑器实例
```

`v5md` 内应形成一个**编辑命令接口**：给定当前选区、命令及可选目标块偏移，返回新的 Markdown、选区和一条撤销历史。视图层负责菜单/拖动反馈，不直接拼接文本；client2 只接收 Markdown 变化并保存，不理解块范围。具体方法名、内部模块划分由实施者决定，但 `getMarkdown`、`undo/redo`、`v-model` 和 `onUploadImage` 的现有用法应保持兼容。

块位置基于解析树的 `start/end` 和 Markdown 源码区间计算。实现者须明确块及相邻空行的归属，覆盖连续段落、列表、围栏代码、表格、frontmatter、首尾空行、CRLF 输入。禁止用标题文本或数组序号当永久块 ID；每次编辑后偏移都可能变化。视图中的操作柄只在当前解析结果中临时定位，拖动开始时冻结源范围，落下前核对文档版本。

`v5md` 为独立仓库且目前包版本为 `0.0.1`。开发时可以用本地构建包做联合验证；发布 client2 时应依赖可复现的明确包版本。设计不要求将其源代码复制进 client2，也不假设当前 registry 上已有这些新能力。

## 应用数据流与保存

1. 选择笔记（ID 字符串）→ `GET /client/notes/{id}` → 得到 Markdown → 初始化 `V5Editor`。只在切换笔记或明确重新载入时调用 `setMarkdown`；常规输入由编辑器内部事务推进。
2. `v-model` 更新当前草稿，记录编辑代次 `draftRevision` 和对应 `noteId`。仅修改当前笔记内容会置 dirty；菜单开关、光标移动和拖动预览不置 dirty。
3. 点击保存或使用 Ctrl/Cmd+S 时，对当前 `noteId`、草稿快照和代次发 `PUT /client/notes`。成功后仅当回复对应的代次仍是当前代次时清除 dirty；若保存期间又输入，新的编辑仍保持 dirty。失败时保留草稿及错误提示，可重试。
4. 切换笔记/退出/关闭窗口：dirty 时提供“保存并继续 / 放弃并继续 / 取消”三种结果；只有保存成功或明确放弃才执行目标动作。macOS 和 Windows 上关闭主窗口时隐藏窗口并驻留托盘；托盘退出也经过相同的 dirty 保护。
5. `v5md` 的撤销是**当前笔记内**的编辑历史；保存不清空历史。切换笔记后分别管理草稿/历史；首期可只保留当前打开笔记的编辑器实例，重新打开时从服务器加载并开始新的撤销历史。没有离线同步承诺。

现有 API 无版本条件，两个客户端同时编辑时可能互相覆盖。首期 UI 应避免把“保存成功”表述为“其他设备没有更新”；若并发编辑成为刚需，再设计服务端版本号和冲突处理。

## 页面与桌面壳

页面采用单侧导航树 + 主阅读/编辑区的两栏布局。左侧以目录树同时显示目录和笔记，树宽约 260–290px；目录可展开或收起，并提供新增、重命名、删除操作，使用一致的 SVG 文件夹、笔记和展开图标。点击笔记先进入只读预览，显式点击“编辑”后才进入编辑状态；预览和编辑复用同一 `V5Editor` 实例，离开编辑态时先保存脏草稿。预览态只保留预览状态与“编辑”；重命名、删除、专注写作操作只在编辑态显示，退出登录只在侧栏底部出现。主区域占满剩余窗口，编辑态移除编辑器外侧的水平留白，不重复显示大号笔记标题，笔记名只出现在紧凑工具栏。侧栏可收起，专注模式将编辑区扩展到全窗并保留明确的退出入口。登录页允许配置服务器地址，首次连通测试后才登录。图片上传沿用 `/basics/base/file` 与现有鉴权头，返回 URL 写入 Markdown。

桌面能力经小型适配层调用。首发平台为 macOS 和 Windows，桌面壳定为 Tauri 2。Tauri 侧只暴露必要的窗口操作及托盘能力；编辑器和业务层不直接导入平台命令。关闭主窗口后应用继续驻留托盘，可从托盘恢复窗口或在 dirty 检查后退出。自动更新、深链和离线数据层不属于此阶段。

## 验证与升级决策

用从既有服务导出的**脱敏副本**建立样本：短笔记、真实长文档、密集列表/嵌套列表、表格、代码围栏、图片、中文段落、frontmatter、CRLF/BOM。对样本做基线保存与重复编辑；不在测试中覆盖原始笔记。

| 检验 | 必须观察 |
| --- | --- |
| 光标/选区 | 长文档首中尾、行内格式边界、菜单打开/关闭、滚动后拖动；输入不跳光标 |
| 中文输入 | 拼音组合、候选词选择、连续输入、撤销；组合过程中 `/` 不误触发 |
| 块操作 | 各可移动类型前后交换、跨多个块移动、无效目标、列表整体移动；原文除目标变动和必要分隔符外不被重排 |
| 历史 | `/` 命令、转换、拖动各一次 Undo/Redo；切换笔记和保存不产生跨笔记撤销 |
| 稳定性 | 在真实长文档上连续输入、搜索、拖动和保存；记录操作耗时、光标错误、丢字和崩溃，定位到具体文档片段 |
| 后端兼容 | 雪花 ID、已有 Markdown 读写、401、上传失败、保存失败、切换/关闭时 dirty 流程 |

测试层次：`v5md/core` 测源码移动与历史（含边缘分隔符）；`v5md/view` 测菜单、拖动、选区和 IME 事件；client2 测登录、保存状态和路由/关闭流程。最后在目标操作系统的真实桌面 WebView 里，用相同样本人工验证中文输入、拖放与光标，不能只靠模拟 DOM 的单元测试。

**决定是否转 JSON 的条件**：若明确需要无法用 Markdown 表达的块属性、任意跨层级重排、稳定块引用或实时协作，或真实样本反复暴露不可接受的源码区间歧义，再提出 JSON 块模型及旧笔记迁移方案。若上述首期交互稳定且原文可保存，就继续保持 Markdown。决策应附失败样本、重现步骤和修复成本，不凭“感觉像 Notion”提前换模型。
