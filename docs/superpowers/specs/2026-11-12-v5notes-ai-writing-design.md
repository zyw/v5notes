# V5Notes AI 功能设计

状态：设计方案（后期规划，未排进当前开发）  
日期：2026-11-12  
范围：`v5notes-client2` 与其使用的 `v5notes2` 笔记 API；可选对接自托管白泽（Baize）AI 控制面。本文只描述设计与分期，不包含业务代码改动。

## 目标

在私有部署的前提下，为 V5Notes 增加可选的 AI 能力。完整产品目标分两层：

1. **AI 写作助手（首期）**：围绕当前笔记与编辑器的改写、摘要、续写、创建新笔记，以及「整篇改写并另存为新文档」。
2. **AI 知识增强（后期）**：跨笔记问答、语义搜索等，不阻塞首期写作助手。

AI 不得破坏现有「数据留在自己服务器」的产品叙事：默认关闭；模型端点与密钥由部署方或用户配置；结果经确认后再写入工作区。

## 选型结论与分期

### 已拍板

| 议题 | 结论 |
| --- | --- |
| 产品分层 | 首期只做 **AI 写作助手**；跨笔记问答 / 语义搜索归后期知识增强 |
| 接入形态 | **笔记侧 AI Gateway（薄层）** 常驻；OpenAI 兼容端点直连为默认路径；白泽作 **可选增强后端**，不作为默认安装依赖 |
| 写回策略 | AI 产出先进预览 / 侧栏；用户确认后再写入编辑器或 **创建新笔记**；禁止静默覆盖 |
| 整篇风格改写 | 支持指定风格（如微信公众号、小红书等）整篇改写；**不修改原文档**，另存为同目录（或用户选择的目录）下的新 Markdown 笔记 |
| 创建笔记 | AI 可根据提示词或当前上下文 **创建新笔记**（标题 + 正文），走现有 `/client/notes` 创建契约 |
| 隐私 | 默认关闭；默认只送选区或当前笔记，不默认扫全库；不持久化用户密码，密钥存放遵循既有设置规范 |
| 旧客户端 / 管理端 | 本期不强制旧客户端；管理端可后续增加模型与开关配置，非首期阻塞项 |

### 不采用

| 方案 | 原因 |
| --- | --- |
| 首期强制依赖整套白泽才能开 AI | 部署过重，违背「装一套笔记就能用」；白泽适合中后期知识增强与多产品共用 |
| 在 Notes 内自研完整 Agent 平台（编排、RAG、MCP、多 Agent） | 与白泽能力重叠，维护成本高；首期固定技能足够 |
| 默认同云端模型、自动外传全文 | 与私有部署卖点冲突 |
| AI 直接静默覆盖当前正文 | 易丢内容；与脏草稿守卫、历史版本语义冲突 |

### 建议实施顺序

```text
Phase 0  配置模型：开关、端点、密钥、超时与长度上限（可先客户端本地或服务端配置）
Phase 1  AI Gateway + 流式输出 + 固定技能（改写/摘要/续写）
Phase 2  创建新笔记、整篇风格改写并另存为新文档（首期写作助手闭环）
Phase 3  可选白泽 Chat 后端；跨笔记问答 / 语义搜索（知识增强，后置）
```

## 已有实现与约束

- 笔记正文在 `note_notes.content`；创建 / 更新走 `/client/notes`；乐观锁使用 `contentHash` / `baseHash`。
- 搜索当前为 `name` / `content` 的 LIKE，无向量索引。
- Client2 编辑器为 `V5Editor`（`@v5md`）；支持 `getMarkdown`、`replaceSelection`、`insertText`、工具栏 / slash / 命令面板扩展点。
- 预览与编辑共用同一编辑器实例；脏草稿离开前须保存或显式丢弃；对话框用应用内模态框。
- 雪花 ID 全程字符串；不持久化密码。
- 产品官网与 README 当前不宣称已具备 AI；AI 属后期规划能力。
- 可选后端白泽（`baize`）：提供 Chat REST + SSE、Agent、RAG、业务工具；**无真正多租户数据隔离**；无笔记增量同步；适合作为可选控制面而非笔记内嵌组件。

## 首期场景：AI 写作助手

### 技能清单

| 技能 ID | 用户动作 | 输入上下文 | 输出落点 |
| --- | --- | --- | --- |
| `rewrite_selection` | 选区改写（润色 / 扩写 / 缩写 / 语气 / 翻译等） | 选中 Markdown 片段 + 指令 | 预览后 `replaceSelection` |
| `summarize` | 摘要 / 提纲 / 待办抽取 | 当前笔记全文或选区 | 预览后插入当前位置，或另存新笔记（可选） |
| `continue` | 续写 | 光标前上下文（截断到上限） | 预览后插入光标处 |
| `create_note` | 由提示创建笔记 | 用户提示词；可选参考当前笔记 | **新建** Markdown 笔记并打开 |
| `restyle_as_new` | 整篇风格改写并另存 | 当前笔记全文 + 目标风格 | **新建**笔记，**不修改**原文 |

### 整篇风格改写（`restyle_as_new`）

典型流程：

1. 用户打开一篇笔记，选择「改写成…」并指定风格预设或自定义说明（例如：微信公众号、小红书、更正式的技术博客、更口语的分享稿）。
2. 客户端将当前正文（受长度上限裁剪或分段策略约束）与风格指令发给 AI Gateway。
3. 流式展示生成结果；用户可编辑预览标题与正文。
4. 确认后调用现有 `POST /client/notes`，在指定 `dirId`（默认与原文同目录）创建新笔记；名称需满足既有校验（必填、trim、≤100 字符），可默认建议为「原标题 - 公众号」一类，允许用户改名。
5. 创建成功后刷新目录树、选中并打开新笔记（建议进入编辑或预览，与「新建笔记」成功路径一致）。
6. 原文的 `id`、正文、`contentHash`、历史版本均不变。

失败时：不创建笔记；保留生成预览供重试；树与当前选中不变。

### 由 AI 创建笔记（`create_note`）

1. 用户打开「AI 创建笔记」，输入主题或提纲要求；可选勾选「参考当前笔记」。
2. 生成标题与 Markdown 正文预览。
3. 确认后走与手工新建相同的创建 API 与对话框规范（成功刷新树并打开；失败留在预览态）。

### 预设风格（首期建议）

首期提供可扩展的风格预设表，至少包括：

- 微信公众号（标题党克制、小标题清晰、段末可带总结）
- 小红书（短句、分点、口语、适合移动阅读；仍输出 Markdown）
- 正式书面 / 技术说明（可后续追加）

预设只影响系统提示词与默认新文件名后缀；用户可追加自定义说明。不在首期做平台账号发布或排版同步。

## 架构

### 推荐形态（分层）

```text
Client2 AI 面板 / 命令 / 工具栏
        │
        ▼
v5notes2  AI Gateway
  · 鉴权（现有登录会话）
  · 功能开关与配额
  · 上下文裁剪与审计日志（可选）
  · 固定技能路由（rewrite / summarize / continue / create_note / restyle_as_new）
        │
        ├── 默认：OpenAI 兼容 Chat Completions / 流式 SSE
        └── 可选：转发白泽 Chat API（Agent + 后续 RAG）
```

### Gateway 职责边界

- **做**：鉴权、开关、超时、token/字数上限、技能 prompt 组装、流式转发、审计（谁、何时、哪篇笔记 id、技能类型；默认不落全文到日志，或可配置脱敏）。
- **不做**：通用 Agent Loop、任意工具调用写库、向量索引、多 Agent 编排（留给白泽或后期）。

### 与笔记写路径的关系

| 动作 | 是否写库 | 使用的现有能力 |
| --- | --- | --- |
| 选区改写 / 续写 / 插入摘要 | 仅改内存草稿，用户保存时走 `PUT /client/notes` | `Draft`、脏守卫、冲突对话框 |
| 创建笔记 / 风格另存 | 确认后 `POST /client/notes` | 名称对话框规范、树刷新、打开笔记 |
| 覆盖原文整篇替换 | **首期不做默认路径**；若未来提供，必须二次确认且可先另存 | — |

## 客户端交互要点

- 入口：命令面板、编辑器工具栏或侧栏 AI 面板；文案需三语（简/繁/英）。
- 流式展示生成中状态；支持取消；失败显示可读错误，不清空原文。
- 所有写回前展示差异或完整预览；「应用到选区」「插入」「另存为新笔记」「创建笔记」为明确主操作。
- 另存 / 创建失败时保留预览；成功后按现有 CRUD 成功路径更新选择。
- AI 生成过程中若用户继续编辑原文：另存仍基于发起任务时的快照或明确提示「原文已变，是否仍用旧快照」，避免静默错写。
- 401 走现有会话失效处理；未保存草稿保留在内存。

## 配置与隐私

| 项 | 要求 |
| --- | --- |
| 总开关 | 默认关；关闭时隐藏或禁用 AI 入口 |
| 端点 | 用户或管理员配置 OpenAI 兼容 Base URL；可选「白泽」模式 |
| 密钥 | 不明文写入仓库；存放位置与现有敏感配置一致（服务端环境变量或加密配置优先） |
| 上下文 | 技能级上限；超长正文截断或拒绝并提示 |
| 出站 | 文档中明确：启用后所选上下文会发往所配置模型服务 |

## 后期：知识增强（不阻塞首期）

- 跨笔记问答、语义搜索。
- 优先评估：白泽 RAG，或 Notes 注册只读业务工具按权限读库；需解决按用户隔离与笔记变更增量索引。
- 不在首期验收范围内。

## 需要修改的实现区域（实施时参考）

本文不改这些文件；清单供后续拆分。

### Client2

- AI 面板 / 命令 / i18n：技能入口、风格预设、预览与确认。
- `EditorPane` / 编辑器命令：选区改写、插入、与 V5Editor API 对接。
- `useWorkspace` / API：确认后创建笔记、打开新笔记、树刷新；复用脏草稿守卫。
- 设置页：开关、端点、密钥、可选后端类型。

### 后端 `v5notes2`

- 新增 AI Gateway 模块或 `note-notes` 下受限端点（如 `/client/ai/...`）：技能枚举、流式代理、配额。
- 配置项与审计；不把模型厂商 SDK 散落到控制器。
- 创建笔记仍只走现有 notes 服务，Gateway 不直接写 `note_notes`（由客户端确认后调创建 API，或 Gateway 提供「生成 + 可选代创建」但须同一鉴权与校验）。

### 可选白泽

- 部署与 Chat API Key / Agent 绑定；Notes Gateway 增加 `provider=baize` 适配器。
- 知识增强阶段再绑定 RAG 或业务工具。

## 验收标准（首期写作助手）

1. 关闭 AI 时，客户端无可用写作助手入口（或入口提示未配置）。
2. 选区改写、摘要/提纲、续写可流式生成；确认后才写入编辑器；取消或失败不破坏原文与草稿。
3. **AI 创建笔记**：确认后产生新笔记，树刷新并打开；取消不建笔记。
4. **整篇风格改写并另存**：原文内容与哈希不变；新笔记在目标目录出现且可打开编辑；默认风格至少覆盖公众号与小红书两类预设。
5. 名称校验、创建失败留预览、成功后选择行为符合现有 CRUD 对话框规范。
6. 雪花 ID 与目录 ID 全程字符串；401 与脏草稿行为与现网一致。
7. 未配置端点或密钥时有明确错误，不发送空请求洗白失败。

## 验证清单

- 短文 / 长文（触发上限）改写与另存。
- 原文有未保存草稿时发起另存：行为符合「快照或提示」设计，不丢草稿。
- 同名冲突或服务端创建失败时的 UI。
- 三语界面与窄屏 / 专注模式下的 AI 面板可用性。
- 关闭开关后回归：无出站调用。

## 非目标

- 修改 `v5notes-client/` 旧客户端。
- 首期交付跨笔记 Agent 自动整理目录、批量改多篇。
- 对接微信 / 小红书账号发布或获取平台草稿箱。
- 在 Notes 内实现完整 RAG 平台或复制白泽控制面。
- 默认可识别的云端「官方 AI 服务」（除非未来单独产品化且明示隐私条款）。

## 由实施者决定

- Gateway 挂在独立 Maven 模块还是 `note-notes` 内受限包。
- 流式协议细节（SSE 事件形状）与前端取消令牌传递。
- 风格预设的最终文案与系统提示词。
- 超长文档是截断、分段多轮合并，还是直接拒绝。
- 设置项放在客户端本地、用户级服务端，还是仅管理员全局配置。
- 白泽适配器的具体 Agent id / API Key 配置命名。
