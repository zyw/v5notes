## 0 · 一句话结论

现在那张紫底三层转圈屏是 RuoYi 默认 loader，跟已批准的「薄荷工作台」主题**不在一个身份里**，而且它没有进度、没有耗时、没有超时/失败退路。要重做的不是「换个转圈的皮」，而是**把加载当作一个界面来设计**：L0 启动 → L1 路由 → L2 骨架 → L3 局部 → L4 按钮 → L5 失败，每一面都要有明确的视觉音量和兜底。

三版已做完，推荐 **方向 1 · 同步进度舱**（信息最实、落地最直接、与薄荷主题最贴），次选 **方向 2 · 梅花的重量**（骨架式，最省事），方向 3 是品牌海报时刻（最出挑、最适合做启动那一下）。

## 1 · 现状诊断（要改什么）

| 面 | 现状 | 问题 | 归属文件 |
|---|---|---|---|
| L0 启动屏 | `index.html` 内联样式：`#7171c6` 紫底 + 三层白色旋转圆环 + `Open Sans` 19px 白字「正在加载系统资源，请耐心等待」 | 紫色与品牌无关（RuoYi 默认）；三层环是 2015 年套路；无进度/耗时/超时/失败路径；Open Sans 未加载则回退系统字 | `v5notes-admin2/index.html` L31-200 |
| L1 路由进度 | `permission.ts` 引 `nprogress/nprogress.css` 默认值 | 进度条是全站唯一一处亮蓝 `#29d` | `src/permission.ts` L3-15 |
| L3 页内加载 | `el-loading` 65 处 | 已改描边色为薄荷，但仍是 Element 默认圆环 + 82% 白遮罩，整卡糊掉、行高 0→54 跳变 | 各 `views/**` |
| L2 骨架 | 全仓 0 处 `el-skeleton` | 每次进页面都是「白卡 + 转圈」，布局跳变 | — |
| L4 按钮 | `useLoading` / `withLoading` | 按钮文字被转圈顶替导致宽度跳动 | `src/hooks/async/useLoading.ts` |

**六个根因**：① 身份断裂（紫 vs 薄荷）② 假等待（无信息）③ 无兜底（不失败/不重试）④ 布局跳变（白卡→数据抖）⑤ 转场生硬（蓝条+白闪）⑥ 层级不分（冷启动与按钮同音量）。

## 2 · 设计系统（六面分层）

| # | 面 | 视觉音量 | 必须做到 | 落地位置 |
|---|---|---|---|---|
| L0 | 启动屏 | 最强，唯一全屏 | 品牌色 + 真实 5 阶段 + 读秒 + 8s 超时兜底 | `index.html` 内联（此阶段无 JS） |
| L1 | 路由切换 | 中 | 2px 薄荷进度条，不遮内容、不闪白 | `permission.ts` + 覆盖 nprogress.css |
| L2 | 页面骨架 | 中 | 骨架形状 = 真实布局的格子（不是灰条堆） | 新 `SkeletonPage` 组件 |
| L3 | 局部取数 | 弱 | 只遮 tbody，保表头与分页 | `v-loading` 收敛 + 区域骨架 |
| L4 | 按钮提交 | 最弱 | 按钮不变宽，转圈在图标位 | 修 `useLoading` / 按钮样式 |
| L5 | 失败/超时 | 特殊 | 说清原因、给重试、保留已加载部分 | 全局错误态组件 |

**共同事件契约**（三版都已实现 `window.LoaderBus` 冒泡，落地时直接接真实事件源）：
`booting → routing → skeleton → partial → (timeout | fail)`；事件 `progress(0..1) / stage(index,label,ms) / done / timeout / fail(reason)`。

**文案**（真实，不用占位）：
- 5 阶段：解析页面骨架 / 载入应用脚本 / 校验会话 / 生成菜单与路由 / 渲染工作台
- 读数：`已用 2.4s`；慢网：`网络似乎较慢，仍在重试…`
- 超时：`加载时间超出预期` + 重新加载 / 查看网络诊断
- 会话过期：`会话已过期，请重新登录`；502：`服务暂时不可用（502）`

## 3 · 三版（完整稿，可点开试用，五面可切、深浅两态可切）

| 版 | 方向 | 骨架 | 胆量 | form 来自内容 |
|---|---|---|---|---|
| **dir-1** | 同步进度舱（最佳设计师） | 居中舱体：真 logo → 140px 真进度环 → 当前阶段+技术子行 → 5 阶段行进清单（带每段实测耗时）→ `步骤 x/5 · 已用 x.xs` 等宽读数 | 把「是不是卡死」用**会动会读秒的真实进度**正面解决 | 产品真的在干 5 件事，清单不是装饰 |
| **dir-2** | 梅花的重量（现实参照 Linear/Vercel） | 真实 admin 骨架透视（236 侧栏 + 64 顶栏 + 4 指标卡 + 表格卡）+ 顶部 2px 薄荷条 | 进度不是「转」，是「先给你一个会长的骨架」——0% 就有布局，内容回来零位移 | 后台是表格的世界，加载先给表格的形状 |
| **dir-3** | 会呼吸的墨（轮盘 · 佐藤可士和） | 左右对开海报：左 52.5% 墨绿满铺 + 反白巨字「等」+ 1px 进度细线；右白底信息区（阶段 / 等宽秒数 / 刻度尺 / 5 阶段刊目） | 把 loading 做成一张**招贴**，不是界面 | admin 也需要「品牌该有的样子」的瞬间 |

三版均：纯内联（0 外链）、橙 logo base64 内嵌、深浅两态真切换、五面真切换、零控制台报错、正文 ≥14px / 标签 ≥12px / 对比度 ≥4.5:1 / 可点 ≥36px。
