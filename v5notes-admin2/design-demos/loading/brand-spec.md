## 3 · 色彩论证（三步法）

1. **采样**：主色不新取，直接继承已批准方向 2 的 `#1c5a48`；深底取已批准抽屉头 `#0f3d33→#1c5a48` 的同一条渐变。品牌橙 `#f60` 系只在 App 图标里出现，**不进 loading 的色板**——它已经和绿色 UI 共存，再进加载面会让两个身份打架。
2. **收敛**：2 个有彩色（薄荷墨绿 H≈160、琥珀 H≈75，色相角差 >60°）+ 1 组中性（画布/卡面/发丝边/墨/次字，明度序列 0.98/1.0/0.93/0.18/0.55）。深底版把薄荷提到 `#4fbf94`（L 差 ≥0.3），保证深底上的对比度。
3. **论证**：**「等待时的颜色必须和到达后的颜色是同一套」**——加载面是用户见到产品的第一秒，如果这一秒是紫的（现状 `#7171c6`）或蓝的（NProgress `#29d`），那薄荷工作台的身份从第一秒就在撒谎。

## 4 · 现状（要改的东西）

| 面 | 现状 | 问题 |
|---|---|---|
| 启动屏 | `index.html` 内联样式：`#7171c6` 紫底 + 三层白色旋转圆环 + `Open Sans` 19px 白字「正在加载系统资源，请耐心等待」 | 紫色与品牌无关；三层环是 2015 年套路；无进度、无耗时、无超时、无失败路径；`Open Sans` 未加载则回退系统字 |
| 路由进度 | `permission.ts` 引 `nprogress/nprogress.css` 默认值 | 进度条是 `#29d` 亮蓝，整站唯一一处蓝 |
| 页内加载 | `el-loading` 65 处 | 统一用了 `--app-accent-strong` 描边（已改），但仍是 Element 默认圆环 + 82% 白遮罩，表格整体糊掉 |
| 骨架屏 | 全仓 0 处 `el-skeleton` / skeleton | 表格每次进页面都是「白卡 + 转圈」，布局跳变 |
| 按钮加载 | `useLoading` + `withLoading` | 按钮文字被转圈顶替，宽度跳动 |
