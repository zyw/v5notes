# 首页设计 spec · V5Notes2 管理控制台首页

> 三个方向的共同输入。只写「要说什么」，不写「长什么样」——长什么样是方向卡的事。
> 尺寸统一 1440×1024（1440 宽桌面浏览器，首屏可见 1024 高），三版必须同尺寸才能横比。

## 1 · 这是什么

V5Notes2 是云笔记产品（Markdown 笔记 + 目录树 + PC/App 双客户端 + 文件附件）。
**管理控制台首页**是管理员登录后落地的第一屏：它要在一屏内回答「我的内容库现在什么样、谁在用、系统稳不稳、我接下来该看什么」。

现状：`src/views/index.vue` 还是 RuoYi 框架自带的营销页（「RuoYi-Vue-Plus 控制台 / 项目矩阵 / 能力地图」），和云笔记业务无关，也没有任何真实统计。本次是**整页替换**。

## 2 · 受众与场景

| 角色 | 打开首页想看到什么 | 时间 |
|---|---|---|
| 产品/内容负责人 | 内容资产规模与增长、哪个目录最活跃 | 每天上午 1 次，看 30 秒 |
| 运营 | 今日新增、活跃用户、谁在写 | 每天多次，扫一眼 |
| 运维/管理员 | 系统健康、异常、在线人数 | 有事才看，要能快速判断 |
| 老板/汇报场景 | 一屏截图能说明「产品在增长」 | 周会/月度 |

共同点：**扫视，不阅读**。首屏决定一切，一屏内要完成「规模 → 趋势 → 异常 → 下一步」的认知链。

## 3 · 核心信息（按优先级）

1. **内容资产规模**：笔记总数 12,486 / 目录 328 / 本周新增 412（+3.4%）
2. **内容增长趋势**：近 30 天新增 vs 编辑，看得到斜率
3. **内容结构**：目录分布（哪个目录是大头）、活跃时段（什么时候在写）
4. **用户与活跃**：用户 1,284 / 在线 42 / 7 日活跃 486 / 今日登录 312
5. **存储**：文件 3,612 / 18.6 GB / 按类型构成
6. **系统脉搏**：接口成功率 99.97% / P95 86ms / 缓存命中 96.4%
7. **最近发生了什么**：最近笔记、实时事件流
8. **下一步动作**：进入笔记管理 / 目录管理 / 查看日志

## 4 · 情感基调

**精密、克制、有分量。** 不是营销页的热闹，也不是大屏可视化的浮夸。
数字要像仪表读数一样可信（等宽数字、明确单位、口径可见）；图表要像金融终端一样干净（少网格线、无渐变堆叠、无双 Y 轴噪音）。
一屏最多一个「视觉重音」，其余全部为它服务。

## 5 · 硬约束

- **主题已锁定**：沿用已批准的「方向 2 · 薄荷工作台 Mint Workspace」令牌（见下）。三版差异在**骨架与信息组织**，不在配色。
- 侧栏 / 顶栏沿用现有外壳：白底、232px 侧栏、薄荷激活块 `#e8f2ec`、logo 用真实 `src/assets/logo/logo.png`。
- 中文字体 MiSans / HarmonyOS Sans SC / PingFang SC；数字用 tabular-nums；小标签用等宽字。
- 可读性：正文 ≥14px、标签 ≥12px、正文对比度 ≥4.5:1。
- 数据全部来自 `data/mock-data.json`（三版同一份，只换设计）。
- 图表用真实 ECharts（`assets/echarts.min.js`，v6.1.0，与项目依赖一致），保证实现可 1:1 落地。
- 交互要真：hover 有反馈、可点、控制台零报错。

## 7 · 数据口径（全部可从现有表算出）

| 指标 | 口径 | 来源表 |
|---|---|---|
| 笔记总数 | `count(*) where del_flag='0'` | `note_notes` |
| 目录总数 | 同上 | `note_directory` |
| 本周新增笔记 | `create_time >= 本周一` | `note_notes` |
| 今日编辑次数 | `update_time >= 今日 0 点` 计数 | `note_notes` |
| 用户总数 / 本周新增 | `count(*)` / `create_time` | `sys_user` |
| 今日登录 / 在线 | 登录日志条数 / Sa-Token 会话数 | `sys_login_info` / 在线会话 |
| 文件数 / 容量 | `count(*)` / `sum(size)` | `basics_file` |
| 操作次数 | 当日条数 | `sys_operlog` |
| 7×24 活跃热力 | `update_time` 按周几×小时分桶 | `note_notes` |
| 目录分布 | `group by dir_id` | `note_notes` |

> 设计稿用 `data/mock-data.json` 的同口径模拟值；接口契约与 SQL 见 `设计方案.md`。
