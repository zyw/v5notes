# 修改用户弹窗 · 三方向

## 设计 spec

- **项目**：V5Notes2 管理端（v5notes-admin2）「用户管理 → 新增/编辑用户」弹窗
- **受众与场景**：工作空间管理员；高频维护成员资料、状态、用户类型与权限
- **核心信息**：用户昵称、归属部门、手机、邮箱、性别、账号状态、用户类型、岗位、角色、备注
- **情感基调**：克制、可靠、清楚，不喧宾夺主
- **输出格式**：1280×1050 桌面视口内的弹窗/抽屉；三版同一内容、同一尺寸
- **设计上下文**：Element Plus 体系；主色 #409eff、标题/标签使用 MiSans / PingFang SC；圆角与阴影沿用 app 的 14px 语言
- **真实资产**：使用 v5notes-admin2 现有 logo（logo.png），无外部图片；邮箱为诚实占位
- **说明**：组件级小改，直接出三版完整稿，未另做六宫格缩略图；本机未装 Python 版 playwright，lint 自动跳过，三版均用 Chrome 截图逐张目检。

## 方向 A · 双栏精修（order / HIG）

- **逻辑与来源**：最佳设计师 — Massimo Vignelli 的网格秩序 + Apple HIG 的表单清晰度
- **借的是什么**：固定 92px 右对齐标签列（彻底解决中文标签换行）、2 列 34px 栏距、细分割线分组、单一蓝色强调
- **主角素材**：真实成员数据本身；不加插画
- **骨架**：940px 居中弹窗，标签在左、控件在右，三段式（账号资料 / 状态与身份 / 权限设置）
- **胆量花在哪**：几乎不用装饰，靠间距和字重建立秩序
- **form 来自内容的哪里**：管理员要在一屏内扫完并改多项资料，所以标签固定、控件对齐、分组最短
- **文件**：dir-1.html / dir-1.png

## 方向 B · 成员摘要 + 分组（editorial）

- **逻辑与来源**：最佳设计师 — 原研哉式留白与“素材即主角” + 成员档案的编辑式左侧栏
- **借的是什么**：暖白纸面、低饱和墨绿、左侧人物摘要（头像/姓名/类型徽标/账号事实）、右侧标签在上、字段分为基本信息 / 组织与权限 / 备注
- **主角素材**：成员头像与身份摘要
- **骨架**：1020px 分栏弹窗，左 300px 身份摘要 + 右表单
- **胆量花在哪**：把“人”放在左栏而不是把表单堆满整屏
- **form 来自内容的哪里**：用户管理不是改一条记录，而是在认一个成员，先给身份再给字段更符合心智
- **文件**：dir-2.html / dir-2.png

## 方向 C · 侧滑抽屉（workspace）

- **逻辑与来源**：现实参照 — 同媒介 SaaS 设置抽屉（Linear / Vercel 式右侧面板）+ V5Notes 墨绿品牌头
- **借的是什么**：右侧滑层保留列表上下文、深色身份头、单列两排字段、底部固定操作与“未保存”提示
- **主角素材**：成员身份头（头像 + 类型 + 部门/岗位）
- **骨架**：610px 右侧抽屉，全高，头部深绿、内容滚动、footer 固定
- **胆量花在哪**：深绿身份头，把编辑动作变成“打开一个人的工作台”
- **form 来自内容的哪里**：用户字段多、编辑时间长，抽屉比窄弹窗更适合纵向浏览，同时不丢掉背后的成员列表
- **文件**：dir-3.html / dir-3.png
