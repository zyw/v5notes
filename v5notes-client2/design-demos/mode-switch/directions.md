# 预览 / 编辑 切换 · 三方向设计记录

日期：2026-11-09　画布：1440 × 900　落点：`v5notes-client2/src/components/EditorPane.vue` + `src/styles/style.css`
原型：`a-pinned-segmented.html` / `b-floating-dock.html` / `c-in-place.html`　索引：`index.html`　截图：`shots/`

## 1 · 起点（现状，已核对）

同一个「切换模式」动作，有两种互不一致的形态：

| | 预览态 | 编辑态 |
|---|---|---|
| 切换控件 | **墨绿实心主按钮「编辑」**（顶栏最右） | **描边次按钮「预览」**（挪到保存左边） |
| 位置 | 最右 | 保存左侧 |
| 形状/轻重 | 主 / 实心 | 次 / 描边 |
| 文案方向 | 指向「将要去」的模式 | 指向「将要去」的模式 |
| 现状状态提示 | 笔记名旁「预览中」文字 | 无（靠保存态） |

问题不在配色或图标，而在**定位成本 + 进出不对称**：每切一次，眼睛要重新在顶栏找「那个和刚才长得不一样的按钮」；进入编辑很显眼，退出编辑又安静又躲在更显眼的保存旁边。用户原话：「切换有点别扭，动线不够好」。

## 2 · form 五问

| | A 定档分段 | B 悬浮双态胶囊 | C 就地编辑 |
|---|---|---|---|
| 叙事角色 | 工作台上一个固定的档位 | 手边一枚会变身的按钮 | 文档自己带着的编辑开关 |
| 观众距离 | 手臂长度，余光可及 | 指尖，贴着正文 | 零距离，落在纸面 |
| 视觉温度 | 中性偏冷，精密 | 中性偏暖，轻浮起 | 最冷，近乎无 chrome |
| 容量 | 顶栏内一个 2 段控件 | 顶栏 0 + 底部浮动胶囊 | 顶栏 0 + 正文角标 |
| 视觉母题 | 档位 / 分段高亮 | 胶囊 / 就地变形 | 细线与纸面 / 状态条 |

## 3 · 三个方向（各出完整版）

### A · 定档分段（`a-pinned-segmented.html`）
- 笔记名右侧一个固定两段开关「预览 | 编辑」，两个选项常显，当前项实心高亮；控件锚在左侧、永不移动。
- 右侧的 命令 / 历史 / 保存 / 更多 / 大纲 随模式增减，但推不动左侧的分段——这是「控件不搬家」的关键。
- 保存仍是独立主按钮（编辑态出现），状态用「已保存 / 保存」表示。
- 适合：改动最小、最稳、老用户零迁移；直接消灭「换副面孔 + 换位置」。

### B · 悬浮双态胶囊（`b-floating-dock.html`）
- 顶栏只留：笔记名 + 预览中 + 命令 + 更多 + 大纲，两种模式下**完全一致**。
- 正文下方浮一枚胶囊：预览态「✎ 编辑」；编辑态原地展开「完成 · 保存」。同一锚点、内容就地变形。
- 「完成」= 若有未保存则先保存、再回预览（原型已模拟）。
- 适合：把编辑器做成写作工具，愿意用浮层换「顶栏不闪」和「控件贴手」。

### C · 就地编辑 · 内容锚定（`c-in-place.html`）
- 顶栏同 B（无模式按钮、两模式一致）。
- 控件落在**正文页面右上角**：预览是安静的小胶囊「✎ 编辑」；编辑是状态条「编辑中 · 未保存 · 完成」。
- **「完成」= 保存并退出编辑**，把「退出」和「保存」合成一个动作，天然满足 AGENTS「切预览前必须先保存成功」。
- 适合：阅读优先、最克制；代价是控件在正文区，可见性弱于顶栏（已常显，不靠 hover）。

## 4 · 六格候选的取舍（每方向两个候选）

| 候选 | 一句话 | 去向 |
|---|---|---|
| A1 定档分段（笔记名旁两段开关） | 一个不动的档位，两选项常显 | **出完整版** |
| A2 单键驻留（同一按钮 编辑⇄完成，改文案不改位置） | 最小改动，位置对称但只显示一个选项 | 备选：省一个控件，但看不到「另一个模式」，仍是切换语义 |
| B1 底部居中双态胶囊 | 贴手、就地变形，顶栏不闪 | **出完整版** |
| B2 顶部右角悬浮胶囊 | 更靠近顶栏习惯位 | 备选：与 C 的角标位置撞，浮层压标题风险更高 |
| C1 正文右上角胶囊 / 状态条，完成=保存退出 | 控件长在纸上，退出=保存 | **出完整版** |
| C2 hover 才浮现的编辑角标 | 最干净 | 备选：纯 hover 有发现性风险，需保留常显兜底 |

## 5 · 三版共同的交互规格（与现状一致或更强）
- 三模式并存：所见即所得 / 源码 / 预览；⌘1 编辑、⌘2 源码、⌘3 预览；⌘K 命令面板。
- 复用同一个 V5Editor 实例（`:key="selectedId"`，只切 `:editable`），Markdown 状态与撤销历史不丢。
- 切到预览若有未保存改动，先保存；失败则留在编辑态（`finishEditing()` 现有逻辑）。
- 预览只读，隐藏格式条；编辑显示格式条与字号 / 隐藏控件。
- 宽度 1440 主设计，≤980 / ≤700 需降级（占位与控件密度收窄）。

## 5.1 · 工具条可见性修正（2026-11-09 反馈后）
- 现象：原型里若点了格式条右端的「隐藏」，工具条会收起，而原型缺少「显示工具条」入口，编辑态看起来就像「没有工具条」。三版均已补上 `格式 ⌘/` 恢复按钮（仅编辑态、工具条收起时出现）。
- 澄清：正常进入编辑态时格式工具条**是显示的**（见 `shots/c-edit.png` 与 `shots/_c_top.png`）；预览态按设计隐藏。落地时同样要保证「隐藏 → 可恢复」这条路径，避免只靠 ⌘/ 快捷键。

## 5.2 · 修正版 D / E / F（2026-11-09 第二轮反馈后）
反馈两点：①B 的底部悬浮胶囊与底部提示气泡同占底部中间，切模式时气泡盖住胶囊；②C 为浮动状态条给正文加了上边距，工具条与首行间距变大。
根因：把切换放在「内容之上/之下」。修正版统一收回顶部，且不动正文上边距：
- **D 居中定档**（`d-header-centered.html`）：两段开关绝对居中于顶栏，永不搬家。
- **E 单键驻留**（`e-single-toggle.html`）：标题右侧一个按钮，编辑⇄完成 原地换字、同尺寸同位。
- **F 工具条行内定档**（`f-in-toolbar.html`）：开关并进工具条左端，该行两模式常驻、编辑时向右展开格式键。
三版均：无底部悬浮控件、无额外上边距、复用同一 V5Editor、保留 ⌘1/2/3。索引：`index2.html`；截图：`shots/d-* / e-* / f-*`。

## 5.3 · 颜值版 G / H / I（2026-11-09 第三轮反馈后）
反馈：D/E/F 不如 A/B/C 好看。本轮保留前三版被认可的质感（悬浮胶囊 / 分段开关 / 纸角标签），同时满足两条硬要求（不占底部、不改正文上边距）。
- **G 滑轨分段**（`g-glide-segmented.html`）：顶栏正中玻璃分段 + 滑动墨绿滑块（260ms）。
- **H 悬浮玻璃胶囊**（`h-glass-capsule.html`）：顶栏右角玻璃胶囊，预览「编辑」→ 编辑态原地展开「完成 · 已保存」；不在底部。
- **I 纸角轻标签**（`i-paper-chip.html`）：保留 C 的纸角悬浮胶囊 / 状态条，去掉额外顶部内边距（工具条到首行恢复原间距）。两处修正：①「完成」补上 data-c-done 处理（保存后回预览），此前缺 handler 点了没反应；②正文右侧预留 176px 页边距作为浮标专用车道，杜绝滚动/长行时压字（实测浮标左缘 > 正文右缘）。
索引：`index3.html`；截图：`shots/g-* / h-* / i-*`。

## 5.4 · J 可拖动纸角标签（2026-11-09 拖动需求）
需求：把纸角标签做成可拖动，并借此消除压字。结论：拖动本身不保证不压字——只有把拖动范围限制在正文之外才成立。因此 J 的做法：
- 拖动范围 = 正文右侧预留的「安全栏」（176px），上下可自由拖动，左右只在该栏内；正文列不进入该栏。
- 松手记住位置（localStorage）；双击回右上角；拖拽中显示虚线安全栏；hover 出现抓取点。
- 实测：把浮标拖到极左/极上会被夹回栏内，浮标左缘 > 正文右缘；普通点击仍可切换模式，拖动后不会误触 click。
- 若要「自由拖到任意位置」，则必须加「松手落在正文上自动弹回安全区」才算不压字；纯自由拖动只是缓解，不是保证。

## 5.5 · K 满宽竖条安全栏（2026-11-09 最终要求）
要求原话：「正文满宽，有安全栏、绝对不压字、可上下拖动记位置」。
关键取舍：正文要满宽，安全栏就不能占用正文宽度，只能借用正文右侧本就存在的页边距（约 44–52px）。因此 K 把标签收成一条**窄竖书签**（40px 宽，图标 + 两字横排），落在既有页边距里：
- 正文列宽不变（doc padding-right 由 44 → 52，仅多 8px，基本满宽）；
- 安全栏 = 右侧 58px 竖条，标签只在此栏内；上下自由拖动，左右被夹住；
- 松手记位置（localStorage），双击回右上角；拖拽时显示虚线安全栏；
- 实测：正文右缘 1373 < 标签左缘 1390，overlap=false；拖到极左/极上被夹回（right 10 / top 8），insideRail=true；点击「编辑 / 完成」正常，拖动后不会误触。
- 代价：栏只有约 52px，标签必须窄；若想要更大的横排标签，就得把栏加宽（正文略窄），二者不可兼得。

## 5.6 · 最终定稿：J 满宽版（2026-11-10）
结论：**J 方案原样，只去掉正文右侧预留留白**（doc padding-right 由 176 改回 44），正文满宽；其余全部保留：
- 贴右悬浮的横版标签（预览「✎ 编辑」/ 编辑「● 编辑中 ｜ ✓ 完成」）；
- 在右侧约 176px 范围内可拖动（上下自由，左右限于右带），松手记位置（localStorage），双击右上归位；
- hover 出现抓取点，拖动时显示虚线活动带；
- 点击与拖动互不误触。
- 说明：默认停在右上空白区；拖到正文行尾可能压到一两个字符，可随时拖开。用户认可该取舍，不再强制留安全栏。

**落地文件：** `j-fullwidth.html`（索引 `index3.html`）。

## 6 · 实现提示（选定后）
1. A：把 EditorPane 头部的 `mode-switch` / `preview-switch` 两个按钮替换成一个 `.seg` 两段控件，绑 `editorMode`；保存按钮保持。改动集中在模板块 + 少量 CSS。
2. B：移除头部模式/保存按钮，新增底部 `.dock`（`position:absolute` 于 `.editor-body`）；`完成` 调 `finishEditing()`；注意给正文留底部安全区、与块菜单 / 查找高亮 z-index 不打架。
3. C：新增正文右上角 `.mode-anchor`；`完成` 调 `finishEditing()`；预览态需给正文额外顶部内边距避免角标压到首行。
4. 任一版都要保留键盘回退路径与命令面板里的模式项，避免只依赖鼠标。

## 7 · 推荐
**A（定档分段）** 作为首选落地：改动最小、风险最低，直接消除「控件搬家 + 进出不对称」这两个核心痛点，且在任何宽度、任何分辨率下都稳定。若用户更看重「编辑时的沉浸感」，选 B；若更看重「阅读优先 + 退出即保存」的语义，选 C。三者也可融合（B 的胶囊 + A 的分段式高亮）。
