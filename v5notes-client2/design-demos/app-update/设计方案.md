# 设计方案 · v5notes-client2 应用内更新

> 范围：桌面客户端检查新版本、下载安装包、安装后重启、展示这一版的更新说明。
> 现状依据：`v5notes-client2` 当前工作区（2026-11-10）。应用是 Tauri 2 单窗口桌面端，版本号 `0.1.0`，只在设置底部用 `getVersion()` 展示，没有更新通道。

## 1. 结论

用 Tauri 官方更新插件完成「检查 → 下载 → 校验签名 → 安装 → 重启」。更新说明是随版本发布的 Markdown，在更新前和重启后各展示一次。

检查地址采用和 v5xs 相同的托管方式：GitHub Release 上的一个固定附件。客户端常量是 `https://github.com/zyw/v5notes/releases/latest/download/latest.json`。`releases/latest/download/` 永远指向当前最新的正式 Release，版本号变了也不用改客户端。不读取用户在设置里保存的笔记服务器，也不请求 `api.github.com`。自定义笔记服务器不能下发客户端安装包。检查更新不携带登录令牌、用户名或笔记内容。

首期只做可选更新。用户可以稍后处理；同一版本自动弹窗只出现一次，设置里仍可再次打开。

## 2. 现状

| 事实 | 位置 | 对更新的含义 |
| --- | --- | --- |
| 版本只在设置底部只读展示 | `src/components/SettingsDialog.vue` | 检查入口放在同一行，不新开一套关于页 |
| 版本同时写在 `package.json`、`src-tauri/tauri.conf.json`、`src-tauri/Cargo.toml` | 三处都是 `0.1.0` | 发布时三处必须相同，以 `tauri.conf.json` 为准 |
| 笔记服务器可切换官方/自定义 | `src/models/serverSettings.ts` | 安装包与笔记服务器无关 |
| 关闭窗口时未保存笔记要先选择保存、放弃或取消 | `src/hooks/useDirtyNavigation.ts` | 重启前走同一套选择 |
| 关闭桌面窗口实际是隐藏，不是退出进程 | `src/utils/window.ts` | 更新完成必须重启进程，不能只藏窗口 |
| 令牌、服务器、上次目录记在本机存储；密码不记 | `src/hooks/useWorkspace.ts`、README | 重启后沿用现有恢复；内存里的编辑撤销历史会丢失 |
| 弹窗用应用内对话框，支持 Escape 取消 | `src/components/WorkspaceDialogs.vue` | 更新过程用同一类对话框 |
| 桌面端已有 autostart 插件；浏览器开发态用 `isTauri()` 判断 | `src-tauri/src/lib.rs` | 开发运行和浏览器里不安装更新 |
| 项目主页已是 `https://github.com/zyw/v5notes`；本仓库 `origin` 就是这个地址 | `src-tauri/src/lib.rs`、`git remote` | 更新清单和安装包发到这个仓库的 Releases，不另建站点 |

## 3. 用户可见的四件事

### 3.1 检查新版本

两个入口：

- 启动后静默检查。打包后的应用启动满 8 秒，且距离上次成功检查超过 6 小时，才请求一次。失败不弹窗。
- 设置底部「检查更新」。登录前后都能点，每次都打开更新对话框并给出明确结果。

结果只有三种，文案分开，不能把失败说成已是最新：

| 结果 | 文案 |
| --- | --- |
| 已是最新 | 当前已是最新版本 |
| 有新版本 | 发现新版本 {版本号} |
| 检查失败 | 暂时无法检查更新，请稍后重试 |

开发运行（`tauri dev`）和浏览器里，按钮可点，结果固定为「当前是开发运行，不能在应用内更新」。不发网络请求。

静默检查发现新版本时打开更新对话框。用户点过「稍后」后，这个版本不再自动弹出；设置底部改为「可更新至 {版本号}」，点它重新打开对话框。手动检查不受「稍后」影响。

若当时已有其他对话框（命名、确认、冲突、个人信息），更新对话框等到它们关闭后再出现，避免两层弹窗叠在一起。

### 3.2 下载新版本

用户在对话框里点「下载并更新」后开始下载。对话框内显示进度：

- 服务端给了总大小：百分比和已下载大小，例如 `42% · 18.6 MB / 44.2 MB`。
- 没有总大小：不定进度，只显示已下载大小。

下载完成前可以点「取消」或按 Escape。取消只中止这一次下载，应用保持原版本继续使用。

下载过程不关编辑器数据。真正替换程序发生在下载完成之后。

### 3.3 更新并重启

下载完成并校验签名通过后，才进入安装。安装开始后对话框不可关闭，主按钮变为「正在安装，完成后将重新打开」，不再响应 Escape。

安装前如果当前笔记有未保存修改，先走现有的保存 / 放弃 / 取消：

| 选择 | 结果 |
| --- | --- |
| 保存且成功 | 继续安装并重启 |
| 放弃 | 丢弃这篇未保存修改，继续安装并重启 |
| 取消，或保存失败 | 不安装。对话框留在「已下载，等待重启」，主按钮改为「完成更新并重启」。笔记和当前页面保持原样 |

版本冲突仍交给现有冲突对话框处理；冲突未解决时不安装。

重启用更新插件配套的进程重启，退出整个进程后再打开新版本。本机存储里的服务器、令牌、上次打开的目录和笔记按现有逻辑恢复。密码仍然不写盘。编辑器撤销历史不保留，所以未保存内容必须在重启前处理完。

平台顺序：

- macOS、Linux：安装返回后调用重启。
- Windows：安装程序会自己关掉并重新打开应用。实现时按插件文档先走「安装然后重启」，并在 Windows 上确认最终只有一个进程；若安装程序已经重启，就不要再调一次重启。

### 3.4 显示更新文档

更新文档是该版本的 Markdown 说明，不是网页，也不是后台富文本。发布时正文写入更新清单的 `notes` 字段。

展示两次：

1. **更新前。** 发现新版本的对话框上方是版本号和发布日期，下方是可滚动的说明。用户据此决定下载还是稍后。
2. **重启后。** 安装前把 `{ version, notes, pubDate }` 写入本机存储。新版本第一次打开时，若存储的版本号等于当前 `getVersion()`，再显示一次「本版更新」。关闭后记下已读版本，同一版本不再自动出现。设置里保留「查看本版更新说明」，有记录就能再次打开。

说明区只渲染受限 Markdown：标题、段落、列表、行内代码、链接。丢掉原始 HTML。链接只允许 `http` 和 `https`，点击走现有的 `open_external_url`。不用 `v-html` 直接塞服务端字符串。

说明为空时，对话框仍可更新，说明区显示「这个版本没有更新说明」。

首期不提供多版本历史列表。清单里只有最新一版的说明；用户看到的是「将要安装的这一版」和「刚刚装好的这一版」。

## 4. 发布物

客户端不新增笔记接口，也不在笔记服务器上放清单。发布物挂在 GitHub Release 上，做法对齐 v5xs（`https://github.com/zyw/v5xs/releases/latest/download/update.json`）：每个正式版上传一个固定文件名的清单，客户端始终请求 `releases/latest/download/`。

两处地址分工不同：

| 用途 | 地址 | 会不会变 |
| --- | --- | --- |
| 检查更新 | `https://github.com/zyw/v5notes/releases/latest/download/latest.json` | 稳定。GitHub 把它转到当前最新正式 Release 里的 `latest.json` |
| 下载安装包 | `https://github.com/zyw/v5notes/releases/download/v0.2.0/<文件名>` | 不可变。写进该版本的 `latest.json`，不使用 `releases/latest/download/` |

清单字段必须是 Tauri 2 更新插件能解析的格式。v5xs 的 `update.json`（`downloads`、`sha256`、`build`）只负责比对版本再打开 DMG，不能原样拿来用。v5notes 要在应用内下载、验签、替换并重启，所以清单用插件规定的 `platforms`。

```json
{
  "version": "0.2.0",
  "notes": "## 新功能\n\n- 可以在应用内检查更新\n",
  "pub_date": "2026-11-10T00:00:00Z",
  "platforms": {
    "darwin-aarch64": {
      "signature": "<app.tar.gz.sig 的全文>",
      "url": "https://github.com/zyw/v5notes/releases/download/v0.2.0/v5notes-aarch64.app.tar.gz"
    },
    "darwin-x86_64": {
      "signature": "<app.tar.gz.sig 的全文>",
      "url": "https://github.com/zyw/v5notes/releases/download/v0.2.0/v5notes-x64.app.tar.gz"
    },
    "windows-x86_64": {
      "signature": "<nsis.zip.sig 的全文>",
      "url": "https://github.com/zyw/v5notes/releases/download/v0.2.0/v5notes-x64-setup.nsis.zip"
    }
  }
}
```

约定：

- 检查地址是代码常量，和笔记 API 的基址不是同一个配置项。打包测试时可以用环境变量 `V5NOTES_UPDATE_FEED` 临时换成本地或某个 tag 的清单；值必须是 `https://`，否则忽略，回退到上面的 GitHub 地址。正式包不依赖这个变量。
- Git tag 带 `v` 前缀（`v0.2.0`），清单里的 `version` 不带 `v`，与 `tauri.conf.json` 的 `version` 相同。插件用语义化版本比较，不高于当前版本就视为已是最新。
- 静态清单始终返回 200。没有更高版本时由客户端自己比较，不要求 GitHub 返回 204。
- Release 必须是公开的正式版。草稿和预发布不会出现在 `releases/latest` 上。私有仓库的附件没有令牌就拉不到，客户端不内置 GitHub token。
- 不走 `api.github.com`。未登录的 API 限额很低，而 `releases/download` 是附件直链，和 v5xs 一样。
- `latest.json` 不提交进 git。发版时按该 Release 上真实存在的更新包生成，避免清单和文件不一致。
- 安装包地址只使用 `https`。签名校验失败则中止，不安装，对话框提示「更新包校验失败，已取消安装」。
- 说明原稿放在 `v5notes-client2/releases/<version>.md`。第一行标题是版本号。发布脚本把正文填进 `notes`，并核对标题与版本一致。GitHub Release 正文用同一份说明。

首期平台：macOS Apple 芯片、macOS Intel、Windows x64。Linux 包等实际开始分发再加进 `platforms`，客户端不用改流程。

首次安装仍用现有的 dmg / nsis 安装包。之后的应用内更新用的是 Tauri 的更新包（macOS 为 `.app.tar.gz`，Windows 为 nsis zip），不是再下一遍 dmg。

发布前置条件，缺了就不要打开这个功能的线上开关：

- 更新私钥只用 minisign 生成，放在构建机或 CI 密钥里，不进仓库。公钥写入 `tauri.conf.json`。
- macOS 安装包需要 Apple Developer ID 签名和公证，否则替换后的应用可能被系统拦住。
- Windows 安装包需要代码签名，否则 SmartScreen 会拦截重启后的程序。

## 5. 客户端结构

更新状态做成纯函数，界面只负责展示和调用插件。网络、签名和安装都不在 Vue 组件里手写。

| 模块 | 职责 |
| --- | --- |
| `src/models/appUpdate.ts` | 阶段流转、进度文案、「稍后」是否还要自动弹、重启后是否要显示说明。单测放在同目录 |
| `src/components/UpdateDialog.vue` | 检查中、有更新、下载中、等待重启、安装中、失败、本版说明 |
| `src/components/SettingsDialog.vue` | 底部版本行增加「检查更新」或「可更新至 …」 |
| `src/hooks/useWorkspace.ts` | 启动静默检查、与现有未保存选择衔接、避免和别的对话框重叠 |
| `src-tauri` | 注册 `tauri-plugin-updater` 与 `tauri-plugin-process`，打开生成更新包，加上对应权限 |

插件配置落点：

- `src-tauri/Cargo.toml`：桌面目标增加 `tauri-plugin-updater`、`tauri-plugin-process`。
- `src-tauri/src/lib.rs`：`setup` 时挂上两个插件，与现有 autostart 一样排除移动端。
- `src-tauri/tauri.conf.json`：`bundle.createUpdaterArtifacts = true`；`plugins.updater.endpoints` 为 `https://github.com/zyw/v5notes/releases/latest/download/latest.json`；写入公钥；Windows `installMode` 用 `passive`。
- `src-tauri/src/lib.rs`：若进程环境里有合法的 `V5NOTES_UPDATE_FEED`，用它覆盖上面的 endpoint。只接受 `https://`。
- `src-tauri/capabilities/default.json`：允许检查、下载、安装和重启。具体权限名以插件注册后生成的 schema 为准，预期包含更新插件的 default 权限和 `process:allow-restart`。
- `package.json`：增加 `@tauri-apps/plugin-updater`、`@tauri-apps/plugin-process`。

不在 Rust 里另写下载器。现有 `reqwest` 只服务导出，不拿来拉安装包。

### 阶段

| 阶段 | 进入条件 | 用户能做的事 |
| --- | --- | --- |
| `idle` | 初始 | 等待检查 |
| `checking` | 开始检查 | 等待；手动检查时可关闭，关闭即放弃这次展示 |
| `current` | 没有更新 | 关闭 |
| `available` | 清单版本更高 | 查看说明；下载并更新；稍后 |
| `downloading` | 用户确认下载 | 看进度；取消 |
| `ready` | 包已下完且签名通过，但安装被未保存内容挡住 | 处理完笔记后「完成更新并重启」 |
| `installing` | 开始替换程序 | 无；等待重启 |
| `error` | 检查、下载或校验失败 | 重试；关闭。失败不改变当前已安装版本 |
| `installed-notes` | 重启后发现刚装好的版本有未读说明 | 阅读；关闭 |

本机只记这三样，都是字符串，不记安装包：

| 键 | 内容 |
| --- | --- |
| `v5notes-update-checked-at` | 上次成功检查的时间 |
| `v5notes-update-dismissed-version` | 点过「稍后」的版本号 |
| `v5notes-pending-release-notes` | 安装前写下的 `{ version, notes, pubDate, seen }` |

新的检查发现更高版本时，清掉旧的「稍后」记录。说明标记 `seen` 之后仍保留正文，供设置里再次查看。

## 6. 对话框

沿用设置弹窗的尺寸语言：暖白底、发丝边、墨绿色文字，宽度约 560px，说明区最高约 280px，超出内部滚动。标题只出现一次。

| 区域 | 内容 |
| --- | --- |
| 眉题 | `UPDATE`；重启后的说明用 `WHAT'S NEW` |
| 标题 | 发现新版本 0.2.0 / 正在下载更新 / 正在安装更新 / 本版更新 |
| 辅助行 | 当前版本 → 新版本；有 `pub_date` 时显示日期 |
| 正文 | 更新说明 |
| 进度 | 仅下载阶段出现 |
| 错误 | 对话框内 `role="alert"`，不关闭对话框 |
| 按钮 | 次按钮「稍后」或「取消」；主按钮「下载并更新」「完成更新并重启」或「关闭」 |

`role="dialog"`、`aria-modal="true"`。检查、说明和下载阶段，Escape 与点击遮罩等于次按钮。安装阶段两者都无效。

设置底部现在是「版本 0.1.0」。改为：

- 平时：`版本 0.1.0` 旁边文本按钮「检查更新」。
- 已知有新版本：文本按钮改为「可更新至 0.2.0」。
- 检查进行中：按钮禁用，文案「正在检查…」。

不在侧栏、工具栏或编辑器上方再放一条更新条。

## 7. 失败与边界

| 情况 | 行为 |
| --- | --- |
| 离线、清单 404 / 5xx，或 GitHub 把请求重定向到登录页 | 手动检查显示失败文案；静默检查不打扰。可重试。没有 Release 或仓库不可公开访问都算失败，不算已是最新 |
| 清单不是合法 JSON，或版本号不是语义化版本 | 视为检查失败，不尝试比较 |
| 当前平台在 `platforms` 里没有对应项 | 「这个系统暂时没有可安装的更新包」 |
| 下载中断 | 停在失败态，已下的半截包由插件丢弃；重试重新下载 |
| 签名不匹配 | 不安装，提示校验失败 |
| 磁盘空间不足 | 展示插件返回的错误信息，停留在当前版本 |
| 应用正在 `tauri dev` 或浏览器 | 不请求清单 |
| 重复点击检查 | 已有一次检查或下载在进行时，忽略新的请求 |
| 从新版本降级 | 不做。清单版本不高于当前版本就视为已是最新 |
| 强制最低版本 | 首期不做 |

## 8. 发布步骤

发布目标就是本仓库的 `origin`：`https://github.com/zyw/v5notes.git`。和 v5xs 不同，这里没有单独的 `github` 远端；tag 和 Release 都推到 `origin`。

1. 同时改 `src-tauri/tauri.conf.json`、`package.json`、`src-tauri/Cargo.toml` 的版本。三处不一致则构建失败。
2. 新增 `releases/<version>.md`，标题与版本号一致。
3. 用更新私钥构建桌面包，生成各平台更新包和 `.sig`。首次安装用的 dmg / nsis 一并打出。
4. 推送 tag `v<version>`，创建**正式** Release（不要标成预发布）。先上传更新包、`.sig` 和首次安装包。
5. 按已上传的文件生成 `latest.json`：`notes` 为说明正文，`signature` 为对应 `.sig` 全文，`url` 为 `https://github.com/zyw/v5notes/releases/download/v<version>/<文件名>`。确认这些地址返回 200 后，再把 `latest.json` 传上同一个 Release。
6. 校验 `https://github.com/zyw/v5notes/releases/latest/download/latest.json` 的 `version`、`notes` 和各平台 `url`。用上一版打包应用走一遍：检查、说明渲染、下载进度、未保存三种选择、重启后说明只出现一次、重启后仍停在原来的服务器和笔记。

## 9. 验收

- 设置里能检查；已是最新、有新版本、网络失败三种文案互不串。
- 有新版本时能读到 `releases/<version>.md` 的标题、列表和链接；说明里的 HTML 标签以文本出现，不会执行。
- 下载能看到进度；取消后版本不变，笔记仍可编辑。
- 有未保存笔记时，保存、放弃、取消三种结果与第 3.3 节一致；保存失败不会重启。
- 签名错误的包不会安装。
- 重启后令牌还在，回到上次的目录和笔记；本版说明出现一次，再次启动不出现；设置里仍能打开。
- 自定义笔记服务器下，更新请求的主机仍然是 `github.com`，不是那台笔记服务器。
- `releases/latest/download/latest.json` 在新正式版发布后指向新清单；预发布不会被已安装的客户端检查到。
- `npm test` 覆盖阶段流转、「稍后」去重、重启后是否展示说明、进度文案。
- 开发运行不发更新请求。
