# spec · V5Notes 官方网站（三方向共用输入）

## 1 · 这是什么
V5Notes 的官方产品站。一套可私有部署的 Markdown 云笔记：桌面端写作、管理后台管人和权限、Java API 把内容收在自己的数据库里。
目标：让第一次来的人 30 秒内明白「它是什么、和网盘笔记有什么不同」，并愿意下载桌面端或去 GitHub 看源码。

## 2 · 受众与场景
- 主要：想自己托管笔记的个人、给家人 / 小团队开账号的人、愿意折腾服务器的开发者。
- 次要：想在一套现成的用户 / 权限 / 笔记 API 上继续做产品的开发者。
- 观看距离：桌面 1440 宽为主（1 米），手机 375 宽要能读。
- 情感基调：安静、可信、具体。不兴奋、不喊口号、不像 SaaS 增长页。

## 3 · 输出格式
- 单页官网，1440×900 为首屏基准；响应式至少验 1440 与 375。
- 单文件 HTML + 同目录相对路径引 assets/ 图片；不引外部 CDN、不引外部字体。
- 页面载入后控制台零报错；导航锚点、按钮、移动端菜单必须能点。
- 不使用 100vh 做区块高度（截图需要整页渲染），用固定 min-height / padding。

### 第 1 段 · 为什么自托管
- 标题：云笔记很好用，直到你想把数据拿回来。
- 导语：本地 Markdown 很自由，但目录、搜索、误删和多设备会把事情变乱。V5Notes 把这两件事合成一套你能自己装、自己备份、自己改的系统。
- 四组对照（左「原来的麻烦」→ 右「V5Notes 的做法」）：
  1. 笔记散在聊天记录、网盘和本地文件夹里 → 一篇笔记就是一份 Markdown，按目录归好，按标题搜索。
  2. 内容存在别人的服务器上 → API、数据库、Redis 和上传文件都由你部署，备份就是拷走三个目录。
  3. 写作界面被管理功能塞满 → 桌面端只留目录、正文和写作工具；用户、角色、审计放在管理后台。
  4. 改乱了，或删错了一整棵目录 → 正文保留历史版本；删除先进回收站，保留 30 天。
- 收束：适合想自己托管笔记的个人、需要给家人或小团队开通账号的人，以及希望在一套现成的用户、权限和笔记 API 上继续做产品的开发者。

### 第 2 段 · 写作
- 标题：打开电脑就能写，换一台接着写。
- 导语：桌面端只有一个目标：让你尽快进入正文。左侧一棵树，右侧一张纸，中间不放大按钮。
- 六条（每条：短标题 + 一句解释）：
  1. 目录与笔记同屏 — 搜索、新建、重命名、删除都在同一棵树里完成，不用在页面之间跳。
  2. 三种模式 — 所见即所得、源码、预览，⌘1 / ⌘2 / ⌘3 直接切；共用同一个编辑器实例，Markdown 状态和撤销历史都还在。
  3. 专注写作 — 收起侧栏，编辑器占满窗口；想回来时，侧栏还在原来的位置。
  4. 大纲与查找 — 长文用右侧大纲定位，⌘F 在当前笔记里查找，不离开正文。
  5. 命令面板 — ⌘K 打开全部命令：切换模式、调整字号、导出 HTML / PDF / Markdown / 长图。
  6. 草稿不丢 — 断网或刷新，未保存的内容还在；切换笔记或关窗口之前会先问你。

### 第 2.5 段 · 核心编辑器 v5md
见 v5md-section.md（逐字文案、事实与三版放置方式）。要点：v5md 是 V5Notes 的核心编辑器，MIT 开源；Markdown 字符串是唯一数据源；标记按需显形；中文输入法友好；粘贴即转换；不锁死框架；可插拔。

### 第 3 段 · 回退
- 标题：删得安心，改得回去。
- 导语：写作里最贵的不是打字，是「刚才那一版去哪了」。
- 三条：
  1. 历史版本 — 正文每次保存留一份快照，可以逐版预览，也可以把任意一版恢复成当前正文。
  2. 回收站 — 笔记和目录先进入回收站，保留 30 天；删除目录时，子目录和笔记一起进去，恢复也是一起回来。
  3. 本地草稿 — 刷新、断网、换一台设备，未保存的内容不会凭空消失。

### 第 4 段 · 管理后台
- 标题：写作之外的事，交给管理后台。
- 导语：管理后台和桌面端共用同一套笔记服务。写的人只管写，管的人在另一个入口。
- 六格：
  1. 用户与组织 — 用户、部门、岗位、角色、菜单、字典、参数、通知，一套系统管理里配齐。
  2. 笔记与目录 — 在后台查看、检索、导出、管理所有人的笔记与目录。
  3. 客户端接入 — 控制哪些客户端可以接入，用哪对公钥完成登录加密。
  4. 审计 — 在线用户、登录日志、操作日志：谁在什么时候做了什么。
  5. 系统监控 — 缓存、接口和运行状态，出问题先看见。
  6. 文件 — 上传内容跟数据库放在一起，备份时一起拷走。

### 第 5 段 · 三端
- 标题：一套笔记服务，同时服务桌面端和管理后台。
- 导语：客户端走 /client/notes，管理后台走 /notes、/system 和 /basics；雪花 ID 从接口到页面始终按字符串处理。
- 三张卡：桌面客户端（Vue 3.5 · Tauri 2）｜ API（Java 21 · Spring Boot 4.1）｜ 管理后台（Vue 3.5 · Element Plus）
- 底部一行：MySQL 8.4 或 PostgreSQL ｜ Redis 7.4 ｜ 本地文件存储 ｜ Flyway 建表

### 第 6 段 · 部署
- 标题：装在自己的机器上，三种方式。
- 导语：数据库表由 API 启动时的 Flyway 创建。选一种方式，把整套系统跑起来。
- Docker Compose 代码块：
    cd v5notes2 && mvn -DskipTests package
    cd ../v5notes-admin2 && pnpm install && pnpm build
    cd ../v5notes2/docker && cp env.example .env
    docker compose up -d --build
- 地址行：管理后台 http://localhost:8988 ｜ API http://localhost:8080
- 另外两条：Jar + Nginx（已有 MySQL / Redis 时）｜ PostgreSQL（同一个开关切方言和 Flyway 目录）
- 备份：数据库 v5notes2/docker/mysql/data ｜ 缓存 v5notes2/docker/redis/data ｜ 文件 v5notes2/docker/uploadfile
- 第一次打开（三步）：用 admin / admin123 登录后台并改密码 → 新建「客户端用户」→ 在桌面端填服务器地址登录。

### 第 7 段 · 技术栈与开源
- 标题：一套能读、能改、能自己维护的栈。
- 左栏技术表：后端 Java 21 / Spring Boot 4.1.2 / MyBatis-Plus / Sa-Token / Flyway / Redisson；前端 Vue 3.5 / TypeScript / Vite / Element Plus / Pinia / UnoCSS；桌面 Tauri 2。
- 右栏三条：
  1. 登录 — 访问令牌只在内存，刷新令牌默认 30 天、一次性轮换；客户端不保存密码。
  2. 三语 — 简体中文、繁體中文、English，三端都能切；后端按 Content-Language 返回提示。
  3. 开源 — Apache 2.0，三个目录可以分开改；接口、表结构和 i18n 都有明确入口。编辑器 v5md 同样以 MIT 开源，可以单独用在别的项目里。

## 6 · 硬约束
- 不编造数据、评价、logo 墙、奖项、客户。
- 正文 ≥16px（桌面），标签 ≥12px；正文对比度 ≥4.5:1；可点区域 ≥44×44。
- 不用 emoji；不用平台字形当图标；图标用内联 SVG。
- 不用「每个标题上一行全大写小标签」、不用「A · B · C」中点、不用「01/02/03」除非真是序列、不给按钮加「→」。
- 交互必须真能点：锚点导航、移动端菜单、部署方式切换（如果做了 tab）。
- 三版同内容，只换设计；每版都要有完整的长页，不是只有首屏。

## 7 · 判断标准
1. 单看首屏截图，像一个认真做过的产品官网，而不是 AI 模板。
2. 不看解释也能看出「这是写笔记的、数据在自己服务器上」。
3. 1440 与 375 都不破版、不横向滚动。
4. 真截图用得像产品，不像装饰。
